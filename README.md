# Growth & Revenue dashboard

Internal dashboard for Work Beyond Borders' Growth & Revenue team. Replaces the
monthly Sales Dashboard spreadsheets with one table and a set of queries over it.

**Preview build — not shared with the team yet.** There is no sign-in, and
nothing is written to a server.

**This repository is private and must stay private.** `site/data/` holds real
prospect company names and contact emails.

## Run it

**Double-click `start-dashboard.cmd`.** It starts the server and opens the
browser. Keep that window open while you use the site — closing it stops the
server, and `localhost:5178` then shows "refused to connect".

Or by hand:

```
python -m http.server 5178 --directory site
```

Then open <http://localhost:5178>.

The server only runs while that window is open; it does not survive a restart,
a log-out or sleep. If the page stops loading, the server has simply stopped —
start it again. This is local only, so it has nothing to do with your network
or where you are.

It must be served over HTTP — opening `site/index.html` from the file system
blocks the `fetch` calls that load the data, and you get an empty dashboard.

## Re-importing

```
python tools/import_sheets.py "../Asset files"
```

Reads every `Outreach Log` sheet it can find, including inside the `.zip`
exports, and rewrites `site/data/`. Safe to re-run; it never modifies the source
workbooks.

Current import: **25,897 rows**, Jun–Nov 2026, contractors AB, HFC, KPK and MAP.

Only the `Outreach Log` sheet is ever read. The `Links` sheet in some workbooks
holds account credentials and personal details — the importer never opens it,
so none of that can reach the site or this repository.

## Why only the Outreach Log is imported

Every other sheet in those workbooks (Monthly Overview, Weekly Overview, Weekly
Breakdown) is formulas over the Outreach Log — the sheets say so themselves.
Importing the log and recomputing the rest is what makes the numbers agree.

In AB's November workbook the log holds 838 rows: 662 have a date, 650 have a
week label. Monthly Overview counted the dated ones, the weekly sheets summed
the labelled ones, and the same month reported two different totals. Here the
week is **derived from the date**, so that class of disagreement cannot happen.

## What the importer normalises

- **Platforms** — `BossJobs`→BossJob, `GlassdoorGlassdoor`→Glassdoor, header
  rows dropped.
- **Statuses** — `Sents`→Sent, `expired`→Lost, `.` and header rows dropped.
- **Dates** — rows with no date are stamped to the first of their workbook's
  month and flagged `inf`. They count toward volume but are excluded from the
  daily-rate chart and from pipeline ageing, because an age computed from a
  fabricated date is not a fact.
- **Duplicates** — same contractor, date, role, company and link counts once.

Every repair is reported on the **Data** page. Nothing is silently dropped.

## Model

Three levels, kept separate on purpose:

- **contractor** — whose outreach it is (AB, HFC, KPK, MAP, and DCA/PNL which
  are deliberately not tracked here)
- **manager** — who owns the contractor and maintains the numbers
  (Apple → MAP, HFC · Rey → AB, KPK · MGP → DCA, PNL)
- **created_by** — who entered the row, for when one person covers for another

Contractors are a filter, never a page of their own, so DCA and PNL cannot
render as empty scorecards.

Monthly targets live in `TARGETS` in `app.js`, taken from the TARGET column of
the Weekly Overview sheets: 400 outreach, 50 responded, 150 warm, 15 calls,
2 closed, per contractor per month.
